# TLSR8266 Mesh Light Project - Development Context

## Crate Layout

Dependencies point one way, and `sdk/check_layering.py` enforces it:

    pac  ->  hal  ->  radio  ->  firmware

| Crate | Path | Owns |
|---|---|---|
| `mesh-protocol` | `rust/crates/mesh-protocol/` | Pure `no_std` wire contracts: packet layouts, CRC, UART framing, mesh opcodes (`mesh_types::LGT_CMD_*`) |
| `tlsr8266-pac` | `rust/crates/tlsr8266-pac/` | Register accessors (`regrw!`) and the host register bank (`fake_mmio`) |
| `tlsr8266-hal` | `rust/crates/tlsr8266-hal/` | `mcu` (clock, crypto, analog, irq), `drivers` (spi, flash, pwm, uart), async runtime |
| `tlsr8266-radio` | `rust/crates/tlsr8266-radio/` | BLE link layer, GATT server, AES pairing, RF driver and mesh link layer |
| `tlsr8266_mesh` | `rust/src/` | Composition root (`app`, `irq`, `startup`, `config`, `version`) and the vertical subsystems (`light`, `mesh`, `ota`, `uart`, `factory_reset`, `diagnostics`, `logging`) |

**`tlsr8266-radio` must never name the application layer** — no `crate::ota`,
`crate::uart`, `crate::mesh`, `crate::light`, `crate::diagnostics`,
`crate::logging`, in production or test code. Everything the radio needs from
above arrives through the `callbacks` and `queues` seams, which `app.rs` installs
once at boot. Adding an upward reference (even behind `cfg(test)`) is exactly
what the extraction exists to prevent; if a radio test seems to need one, fake
the input instead.

## Hardware Platform

**Target MCU:** Telink TLSR8266F512 BLE SoC
- 32-bit RISC processor @ 32MHz (up to 48MHz)
- Custom ARM core without ARMv6 features, only Thumb support, functionally equivalent to ARM920T
- 16KB SRAM, 512KB Flash
- Constraints: Limited memory requires careful resource management
- Power modes: Active, Idle, Suspend, Deep Sleep (~1ms transition)

**Wireless:**
- BLE 4.2 transceiver (1Mbps standard, 2Mbps proprietary)
- +7dBm output, -92dBm sensitivity

**Key peripherals:**
- GPIO: Up to 35 pins
- Communication: UART, I2C, SPI, USB
- ADC, PWM, Timers, KeyScan, AES engine

## Project Coding Standards

### Testing Style

**Tests in Same File** - In Rust, it's idiomatic to include tests in the same file as the code they test. Place tests in a `mod tests` block at the end of the file with coverage disabled:
```rust
// Implementation code here...

#[cfg(test)]
#[coverage(off)]
mod tests {
    use super::*;

    #[test]
    fn test_some_function() {
        assert_eq!(some_function(1), expected_result);
    }
}
```

**Coverage Attributes** - All test modules should be marked with `#[coverage(off)]`, immediately after `#[cfg(test)]`.

**Test Isolation** - There is no call-graph mocking framework any more (the old `mry` crate was removed when the radio moved out of the binary crate). Hardware is faked instead, and every fake is a process-wide singleton (one register bank, one 512 KiB flash array, one clock, one AES mode per test binary). Two consequences:

1. The suite runs with `--test-threads=1` (`rust/run_tests.sh` passes it for you).
2. Every test that touches a fake resets it in its fixture, so no test inherits another's writes:

```rust
use tlsr8266_hal::drivers::flash::fake_flash::FakeFlash;
use tlsr8266_hal::mcu::analog::fake_analog::FakeAnalog;
use tlsr8266_hal::mcu::clock::fake_clock;
use tlsr8266_hal::mcu::crypto::fake_crypto;
use tlsr8266_pac::fake_mmio::FakeMmio;

fn reset_fakes() {
    FakeMmio::reset();
    FakeAnalog::reset();
    fake_clock::reset();
    fake_crypto::reset();
    FakeFlash::reset();
}
```

**Testing Async Functions** - Async functions are still tested from a synchronous `#[test]` by driving the future to completion:

```rust
#[test]
fn test_async_function() {
    let result = futures::executor::block_on(async_function_under_test());
    assert_eq!(result, expected_value);
}
```

### Testing the Application Layers

There is no mockable global `App`: the managers own their own state, and tests
drive the real functions. Reset through the module's own `reset_for_test()`
helper (`crate::ota::reset_for_test`, `crate::uart::reset_for_test`,
`crate::mesh::reset_for_test`, `crate::factory_reset::reset_for_test`,
`crate::light::effects::reset_for_test`, `crate::light::transitions::reset_for_test`),
plus `tlsr8266_radio::callbacks::reset_for_test()` and
`tlsr8266_radio::queues::reset_for_test()` for the radio seams.

Prefer asserting observable behaviour — returned values, subsystem state, the
`FakeMmio` write log, flash contents — over asserting that some internal helper
was reached. A test whose only claim is "this function called that function" is
a test of the implementation, not of the behaviour.

### Documentation Style

**Function Documentation** - Use doc comments with this structure:
```rust
/// Brief single-line description of function purpose.
///
/// More detailed explanation about what this function does.
///
/// # Parameters
///
/// * `param_name` - Description of parameter
///
/// # Returns
///
/// * Description of return value/type
///
/// # Notes
///
/// * Any special considerations or implementation details
```

**Enums** - Comment each variant:
```rust
enum GattOp {
    AttOpErrorRsp = 0x01,       // Error Response op code
    AttOpExchangeMtuReq = 0x02, // Exchange MTU Request op code
}
```

**In-Code Comments:**
```rust
// --- Major section of code ---

// 1. First, retrieve the count
let count = get_count();

data[0] = CMD_READ;    // Command byte
data[1] = 0x01;        // Address (low byte)
```

### Code Structure

**File Organization:**
- Imports and extern declarations at the top
- Constants and public enums next
- Public functions, then private functions
- Tests in a module at the end with `#[cfg(test)]` and `#[coverage(off)]`

## BLE Implementation Notes

- Project implements BLE mesh networking for lighting control
- Attributes use 16-bit or 128-bit UUIDs
- Handle ranges and attribute discovery follow BLE ATT protocol
- Low memory requires efficient attribute search algorithms
- L2CAP ATT handler is core component for BLE communication

## Memory Considerations

- 16KB SRAM restricts buffer sizes - use minimal sized buffers
- Flash sector size is 4KB - align updates to these boundaries
- When writing flash, organize data to minimize erase operations
- Deep Sleep should be used whenever possible to extend battery life
- Data structures should be memory-aligned for optimal access

**Memory Map:**
- SRAM: 0x808000 – 0x80BFFF
- Register area: 0x800000 – 0x807FFF
- Flash (mapped via SFC): 0x000000 – 0x07FFFF
- Boot ROM: 0x70000 – 0x7FFFF

## Common Patterns

- Use `slice::from_raw_parts` carefully when working with raw pointers
- For BLE operations, handle both 16-bit and 128-bit UUID cases
- Check buffer sizes before operations to prevent overflows
- Restore original values after modifying attributes in tests
- Use `addr_of_mut!` macro when working with raw pointers to maintain safety
- Host-only helpers are gated on `cfg(not(target_os = "none"))`, never on
  `cfg(test)`: a crate compiled as a *dependency* does not receive the
  dependent crate's `cfg(test)`, so a `#[cfg(test)]` fake is invisible to the
  firmware's own tests. The firmware image must not contain them.

## Host Test Fakes and Seams

The same code that ships to the MCU runs on the host: each peripheral has a host
implementation that the real accessors drive, so tests exercise production paths
rather than stubs.

### Registers — `FakeMmio`

`tlsr8266_pac::fake_mmio::FakeMmio`. Every `read_reg8/16/32` and
`write_reg8/16/32` off-target goes through this bank, so you seed inputs and
assert on what the code wrote:

- `set_reg8/set_reg16/set_reg32(addr, v)` — seed a value without logging a write.
- `reg8/reg16/reg32(addr)` — inspect the bank without going through a read hook.
- `on_read8/on_read16/on_read32(addr, hook)` — take over reads of one address; the
  hook receives the per-address call index (0 on the first read), which models
  polling loops.
- `writes()` — the ordered `Vec<RegWrite { addr, width, value }>` of every accessor
  write since the last reset; `clear_writes()` drops the log but keeps the bank.

```rust
use tlsr8266_pac::fake_mmio::{FakeMmio, RegWrite};

#[test]
fn test_rf_set_ble_access_code_adv() {
    FakeMmio::reset();

    rf_set_ble_access_code_adv();

    assert_eq!(
        FakeMmio::writes(),
        vec![RegWrite { addr: 0x408, width: 4, value: 0xd6be898e }],
        "the advertising access code must reach reg_rf_access_code"
    );
}
```

Addresses in the log are normalized (`addr | REG_BASE_ADDR`), so assert with the
same constant the code writes, not a hand-computed absolute address.

### Flash — `FakeFlash`

`tlsr8266_hal::drivers::flash::fake_flash::FakeFlash`. A 512 KiB in-memory NOR
device; `flash_read_page`, `flash_write_page` and `flash_erase_sector` drive it
directly in the default `FakeFlashMode::InMemory` mode.

- `read_slice(addr, &mut out)` / `write_slice(addr, &data)` — seed and inspect.
- `erase_count(addr)` — how many times the sector was erased.
- `fail_verify_next_write()` — force the next write/verify to fail, for recovery paths.
- `set_mode(FakeFlashMode::SpiRegisters)` — opt in to driving the real `mspi_*`
  transactions through `FakeMmio`, for tests whose subject *is* the SPI protocol.

### Clock — `fake_clock`

`tlsr8266_hal::mcu::clock::fake_clock` owns `reg_system_tick` and the `sleep_us` log:

- `set_ticks(u64)`, `advance_ticks(delta)` (adds whole 32-bit wraps),
  `set_xtal_16mhz(bool)`, `sleeps() -> Vec<u32>`.

### AES — `fake_crypto` / `SoftwareAes`

`tlsr8266_hal::mcu::crypto::fake_crypto`. The default mode is
`FakeAesMode::SoftwareAes`: a real FIPS-197 AES-128 in pure Rust, with the chip's
byte-reversal parity, so pairing and packet encryption behave exactly as on
silicon. Use `FakeAesMode::MmioRegisters` only when the test's subject is the
`0x540`/`0x548`/`0x550` write-poll-read sequence.

### Radio → application seams

`tlsr8266_radio::callbacks::{set_ble_app_hooks, set_ota_hooks, reset_for_test}`.
The radio calls the application through `fn`-pointer structs; a test installs
recording or scripted hooks and asserts on what the radio dispatched.

```rust
use tlsr8266_radio::callbacks::{set_ble_app_hooks, BleAppHooks};

static LIGHT_DATA_CALLS: AtomicUsize = AtomicUsize::new(0);

fn record_light_data(_pkt: &Packet) {
    LIGHT_DATA_CALLS.fetch_add(1, Ordering::Relaxed);
}

fn install_recording_hooks() {
    LIGHT_DATA_CALLS.store(0, Ordering::Relaxed);
    set_ble_app_hooks(BleAppHooks {
        on_mesh_pair_proc: || {},
        on_light_data: record_light_data,
        on_light_response: |_rsp, _src| Err(()),
        on_uart_mesh_rx: |_pkt| {},
    });
}
```

`OtaHooks` follows the same shape (`on_gatt_ota_write`, `status_snapshot`,
`request_termination`, `tick_timeout_1s`). On host builds both seams start
populated with inert defaults, so a test that does not care about a seam needs no
setup; `callbacks::reset_for_test()` restores those defaults and clears the OTA
stand-in.

`tlsr8266_radio::queues::reset_for_test()` clears the mesh RX/TX and UART TX
queues, the wake flag and the drop counters.

### Rules

1. Reset every fake you touch at the start of the test, and assume nothing about
   the previous test.
2. Assert behaviour, not call edges: returned values, subsystem state, the
   `FakeMmio` write log, flash contents, queue contents.
3. Never widen visibility to make a test reachable — drive the public entry point
   or install a seam instead.
4. Run the whole workspace after a change: `cd rust && ./run_tests.sh`. For a
   fast 64-bit loop: `cargo test -p tlsr8266-radio -- --test-threads=1`.
5. Host fakes are `std`-only and gated on `cfg(not(target_os = "none"))`; never
   let one leak into the firmware image.
