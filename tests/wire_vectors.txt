# wire_vectors.txt -- cross-boundary golden vectors for the TLSR8266 mesh
# firmware (Rust, rust/src/wire_contract_tests.rs) and the host tooling
# (Python, utilities/meshutils/tests/test_wire_contracts.py).
#
# Format (normative):
#   * one `key = value` per line; blank lines and lines starting with `#`
#     are ignored; keys are dot-namespaced and MUST be unique;
#   * a value is a decimal integer, a 0x-prefixed hex integer, a
#     space-separated list of lowercase 2-hex-digit bytes, or a bare string;
#   * the accessor chosen at the parse site decides the kind, so a value that
#     looks numeric (pair.default.password = 123) is read as a string there.
#     Single-token values are therefore ambiguous by design: '00' is one
#     byte for crc.v1.input, and size.AppCmdValue = 20 is decimal twenty.
#     Each suite must classify via the accessor it calls, never by shape.
#   * uuid.* values are 32-character bare strings (canonical display order),
#     not byte arrays, even though every character is a hex digit.
#
# Generated by tests/generate_wire_vectors.py, which imports the real Python
# tooling (mesh_common.crc16, mesh_common.aes_att_encryption,
# mesh_common.decrypt_notification, mesh_common.process_session_key,
# BLEPacketParser, UARTPacketParser). Never hand-edit this file:
# change the generator, re-run it, then re-run both suites.
#
# SYNTHETIC values are called out with an explicit `# SYNTHETIC` comment and
# mirrored as their own keys so neither suite has to pretend they are facts.

# --- Session-key derivation (mesh_common.process_session_key) -----------

# --- Firmware header (first 32 bytes of the image, sdk/cstartup_8266.S) --
# [0:2]   reset branch opcode   -- SYNTHETIC, see ota.header.reset_opcode
# [2:6]   BUILD_VERSION u32 LE, bit 31 clear (rust/src/version.rs)
# [6:8]   zero (the .org 0x8 gap)
# [8:12]  .word 0x544c4e4b little-endian => 4b 4e 4c 54, i.e. 'KNLT' on flash
# [12:16] .word 0x00880120 (RAM-code size word), see ota.header.ramcode_word
# [16:18] IRQ branch opcode     -- SYNTHETIC, see ota.header.irq_opcode
# [18:24] zero (.org 0x18 gap)
# [24:28] _bin_size_ u32 LE (matches ota.blob length)
# [28:32] zero placeholder: a real image carries FW_DEV_INFO (0x00000004);
#         neither tool reads this word, so it is not asserted anywhere.
